# TASK 시작 입력 체크리스트

## 1. 문서 책임

이 문서는 TASK 시작 전에 필요한 입력을 확인하고 안전하게 자료를 요청하는 단일 기준이다.
전체 workflow는 `docs/process/DEVELOPMENT-WORKFLOW.md`, GPT 단계별 입력 계약은 `docs/process/GPT-REVIEW-CONTRACT.md`를 따른다.

특정 magic phrase는 요구하지 않는다.

## 2. 시작 상태

TASK를 시작하기 전에 다음 항목을 확인한다.

| 항목 | 확인 내용 |
| --- | --- |
| TASK | TASK ID와 목적 |
| Phase | 현재 승인된 단계 |
| allowed work | 이번 단계에서 허용된 파일·명령·작업 |
| prohibited work | 금지된 파일·명령·작업 |
| baseline | 기대 branch와 SHA |
| required input | 구현·검토에 필요한 핵심·보조 자료 |
| blockers | 핵심 입력 누락, 상태 불일치, Critical 등 중단 조건 |

하나라도 현재 단계 진행을 차단하면 추정으로 채우지 않고 중단 사실을 보고한다.

## 3. 자료 요청 원칙

1. TASK 목적과 유형을 먼저 확인한다.
2. 현재 단계에서 필요한 핵심 자료와 보조 자료를 구분한다.
3. 실제 저장소에서 존재하는 상대 경로를 확인한다.
4. 확인된 경로 중 필요한 최소 범위만 요청한다.
5. 존재하지 않는 경로를 관례나 기억으로 만들어 요청하지 않는다.
6. ErrorCode, Redis, 전체 package 등 관련 없는 자료를 모든 TASK에 일괄 요청하지 않는다.
7. 한 번에 큰 저장소 전체를 덤프하도록 요구하지 않는다.
8. 현재 Phase를 차단하는 핵심 입력이 부족하면 해당 단계 작업을 시작하지 않고 부족한 항목을 명시한다.

GPT 리뷰의 핵심·보조 입력 분류와 누락 처리는 `docs/process/GPT-REVIEW-CONTRACT.md`를 단일 기준으로 따른다.

## 4. TASK 유형별 판단

고정 파일 목록을 모든 TASK에 강제하지 않는다.
아래 질문으로 실제 필요한 자료를 좁힌다.

### 코드 동작 변경

- 변경 대상 코드와 직접 호출·피호출 문맥은 무엇인가?
- 관련 테스트와 실패 경로는 무엇인가?
- transaction, concurrency, state, Redis, DB 영향이 있는가?

영향이 있는 영역의 실제 파일만 요청한다.

### 문서·프로세스 변경

- 변경 대상 문서의 책임과 참조 대상은 무엇인가?
- 기존 SSOT와 중복되는가?
- 변경으로 깨질 수 있는 링크나 validator 규칙이 있는가?

### DB / Flyway 변경

- `docs/db/README.md`와 현재 migration 경로를 먼저 확인한다.
- 기존 migration 수정 여부와 새 migration 필요성을 구분한다.

### 인증·보안 변경

- 현재 TASK에 직접 관련된 인증·보안 코드와 설정만 요청한다.
- secret 값 자체를 요청하지 않는다.

## 5. 민감정보 요청 금지

다음 경로의 본문을 요청하거나 출력하지 않는다.

```text
.env
.envrc
.direnv
```

동일 목적의 secret 파일이나 실제 credential 값도 요청하지 않는다.

필요한 경우에는 다음과 같이 비밀값이 아닌 구조만 확인한다.

- 변수 이름
- placeholder 여부
- 설정 경로 존재 여부
- 비식별화된 실패 정보

민감정보가 실수로 제공되면 저장소 문서나 검토 결과에 다시 복사하지 않는다.

## 6. 고정 패킷과 일반 작업

### 고정 패킷 검토

사용자가 검토 자료를 고정 패킷으로 정의하면 해당 패킷 안의 정보만 사용한다.
패킷 밖 대화, 저장소 추정, 외부 정보를 보충하지 않는다.

### 일반 프로젝트 작업

승인된 이전 결정과 상태를 사용할 수 있다.
다만 branch, SHA, 파일 내용, 기술 설정처럼 변경 가능한 사실은 현재 근거로 다시 확인한다.
과거 맥락과 현재 근거가 충돌하면 현재 근거를 우선한다.

상세 GPT 입력 규칙은 `docs/process/GPT-REVIEW-CONTRACT.md`를 따른다.

## 7. 자료 확인 후 흐름

1. TASK와 현재 Phase를 확인한다.
2. baseline과 작업 범위를 확인한다.
3. 필요한 핵심·보조 입력을 확인한다.
4. blocker가 있으면 다음 주요 단계로 진행하지 않는다.
5. 입력이 충족되면 현재 Phase에서 허용된 작업만 수행한다.
6. 다음 주요 단계는 사용자 승인 없이 자동 진행하지 않는다.
