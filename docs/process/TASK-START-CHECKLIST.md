# TASK 시작 체크리스트

## 목적

TASK 이슈와 구현 범위를 정하기 전에 필요한 최소 자료를 확인한다.
존재하지 않는 특정 파일을 모든 TASK의 공통 입력으로 강제하지 않는다.

## 1. TASK와 로드맵 확인

- TASK 번호와 작업 목적
- `docs/process/PORTFOLIO-ROADMAP.md`의 현재 상태와 선행 조건
- 기존 GitHub Issue 존재 여부
- 현재 단계가 이슈 초안, 설계, 구현, 리뷰 또는 Git 작업 중 어디인지

## 2. 저장소 상태 확인

프로젝트 루트에서 필요한 범위만 확인한다.

```bash
git rev-parse --show-toplevel
git branch --show-current
git status --short
git log --oneline -5
```

- 원격 URL 전체 출력은 요청하지 않는다.
- 작업 트리에 변경이 있으면 기존 변경과 현재 TASK의 관계를 먼저 확인한다.
- 승인 없이 브랜치를 생성하거나 전환하지 않는다.

## 3. 모든 TASK의 공통 자료

- 이슈 또는 승인된 요구사항
- 목표와 구현 범위
- 완료 조건
- 테스트 계획
- 영향받을 것으로 예상되는 기능
- 현재 구조를 확인할 수 있는 관련 파일 경로

## 4. TASK 유형별 최소 자료

### 기존 기능 수정

- 수정 대상 코드
- 호출하는 코드와 호출받는 코드
- 관련 테스트
- 현재 실패 또는 변경이 필요한 동작의 근거

### 신규 기능 또는 도메인

- 가장 가까운 기존 구현의 실제 경로
- 새 기능의 API 또는 입출력 요구사항
- 상태 전이와 저장 데이터
- 예외와 권한 요구사항
- 테스트 시나리오

### 트랜잭션·동시성·멱등성

- 트랜잭션 시작과 종료 위치
- 상태 변경 코드와 Repository 호출
- 락 또는 원자 연산 코드
- 중복·동시 요청 시나리오
- 실패·롤백·재시도 테스트

### Redis·캐시·대기열·Rate Limit

- 실제 Redis 접근 코드
- Key 생성 위치
- TTL과 정리 방식
- Lua 또는 원자 연산 사용 위치
- Redis 장애 시 동작
- 단위·통합 테스트

### DB·Flyway

- 현재 Entity와 Repository
- 관련 스키마와 최신 마이그레이션 목록
- 인덱스와 제약조건
- 기존 마이그레이션 수정 여부
- 롤백 또는 호환성 영향

### 인증·보안

- 실제 Security 설정과 인증 흐름
- 권한 검증 위치
- 민감정보 처리 방식
- 실패 응답과 보안 테스트

### 테스트·인프라·문서

- 현재 실행 명령과 설정 파일
- 관련 CI 또는 Docker 설정
- 기존 테스트와 실행 결과
- 변경 대상 문서의 실제 경로

## 5. 민감정보 요청 금지

- `.env`, `.envrc`, 비밀번호, 토큰, API Key와 인증 헤더의 값을 요청하지 않는다.
- 필요한 경우 파일 존재 여부, 변수 이름 또는 비식별화된 실패 상태만 요청한다.
- 토큰이 포함될 수 있는 원격 URL 전체 출력을 요청하지 않는다.
- 사용자 절대 경로와 세션 식별자를 저장소 문서에 기록하지 않는다.

## 6. 자료 확인 후 흐름

1. 필요한 자료가 모두 확인됐는지 판정한다.
2. 부족한 자료가 있으면 이슈나 구현을 시작하지 않는다.
3. 자료가 확인되면 이슈 초안을 작성한다.
4. `ISSUE_REVIEW`를 진행한다.
5. 사용자가 이슈와 설계를 승인한 뒤 구현 단계로 이동한다.
6. 다음 단계는 사용자 승인 없이 자동 진행하지 않는다.
